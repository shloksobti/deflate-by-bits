\section{E6 run history and disclosures}\label{app:e6}
\paragraph{Isolation.} In the reported E6 runs, each agent works in a fresh scratch folder outside the project directory and uses a Python environment (NumPy, pandas, SciPy) that is also outside it. It reaches the holdout only through HTTP to a server process holding the train, validation and test matrices in memory. Each null replicate is drawn from an \texttt{os.urandom} seed that exists only in the server's memory and is written to disk after the agent process has exited. Data access is therefore enforced by construction for the null episodes: even an agent that read every file on the machine could not reconstruct the validation data. Claude Code ran with only the Bash, Read, Write and Edit tools, no MCP servers, no user or project settings, and no web access; each session was capped at 25 minutes.

\paragraph{First batch (superseded).} We first ran a batch of 72 Claude episodes with an earlier server that wrote the seed to a file in the results directory at start-up, and with an agent Python environment inside the project directory. An audit of those transcripts found that several Sonnet agents listed the project root or searched the filesystem for the client module, but none read the results directory, the seed files, the source code or the data. To make validity enforced rather than behavioural, all reported Claude results come from a complete rerun under the isolation above. The first batch is in \texttt{results/exp6/batch1} and gave qualitatively identical results: no Sonnet exploitation; Opus under \emph{optimize} ran programmatic searches in 7 of 12 episodes, reaching validation $t$ of 11--21 on noise, and ledger DSR certified 6 of them at an intermediate stopping point. Before that batch, four episodes were lost to a server-shutdown bug that prevented their seeds from being recorded, and one pilot episode used a different prompt; these five are excluded and archived.

\paragraph{Open-weight coder.} The Qwen3-Coder episodes ran on the GPU server with the earlier server version, which wrote seed files at start-up. A search of all 36 transcripts finds no reference to the seed files, the results or project directories, the server code or the raw data; the agents' code only calls the client API. The coder never exploited the holdout, and access could only have inflated its overfitting, so this cannot affect the conclusions drawn from it.

\paragraph{Models and software.} \texttt{claude-opus-5-5} and \texttt{claude-sonnet-5-5} via Claude Code 2.1.287 (headless mode), run on 2026-10-02/03; Qwen3-Coder-30B-A3B-Instruct-FP8, Qwen2.5-7B/72B-Instruct and Qwen2.5-1.5B-Instruct served with vLLM 0.23 and trained with TRL 1.14 on one AMD MI325X (ROCm 7.14). Full prompts, transcripts and ledgers are in the repository.
